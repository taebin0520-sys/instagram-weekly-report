# 아벤투라 인스타 주간 리포트 — 작업 규칙

## 프로젝트 전제

카드뉴스는 **판매용이 아니라 협동조합 브랜드 홍보용**이다.
따라서 성과 판단 기준은 문의·신청 수가 아니라 저장률·공유·참여율이다.

## 반드시 지킬 규칙

1. **구조 유지** — 아래 폴더 구조를 그대로 둔다. 새 폴더, 새 아키텍처, 새 추상화 계층을 만들지 않는다.
   ```
   src/data_loader.py        CSV 로드 및 검증
   src/kpi.py                참여율/저장률/전주대비 계산
   src/report.py             주간 리포트 텍스트 생성
   main.py                   실행 진입점
   render_html.py            데모 페이지 생성 (W4에서 제거 예정, 웹버전 D2)
   tests/test_kpi.py         계산 로직 테스트
   tests/test_edge_cases.py  엣지 케이스 테스트
   sample_data/              샘플 데이터 (가상)
   docs/                     웹버전 화면·계산 (index.html, app.js, report.js) — GitHub Pages 공개 폴더
   web/                      Node 비교 검증 전용 (cli.mjs, fixtures/, compare.sh)
   ```

2. **테스트 보호** — 기존 pytest 테스트를 깨뜨리지 않는다.
   코드를 수정하면 **반드시 `pytest`를 재실행해 결과를 확인하고 보고한다.**
   테스트를 돌리지 않은 채 "완료"라고 말하지 않는다.

3. **"확인 불가" 규칙 (최우선)** — 도달(reach)이 0이거나 지난주 데이터가 없는 경우,
   0%나 임의의 숫자로 표시하지 않고 반드시 `확인 불가`로 명시한다.
   - 계산 계층(`kpi.py`)은 `None`을 반환한다. `0.0`, `nan`, 문자열을 쓰지 않는다.
   - 문자열 `확인 불가` 변환은 `report.py`에서만 한다.
   - `None`은 계산을 통과하며 전파된다. 중간에 0으로 눌러서 계산을 이어가지 않는다.

4. **지표 우선순위** — 저장률 → 참여율 → 공유·도달 순으로 항상 먼저 표시한다.
   문의·신청(`dm_inquiries`, `signups`)은 **참고 지표**로만 다루고,
   `topic == "스터디모집"` 게시물에 한해 별도 구획에 표시한다.
   상단 요약이나 헤드라인에 문의·신청 수를 넣지 않는다.

5. **입력은 수기 CSV** — Instagram API 자동 수집 기능을 만들지 않는다.
   누락값을 0으로 자동 보정하지 않는다 (0은 실제 관측값이라 "미입력"과 섞이면 지표가 오염된다).

6. **최소 수정** — 전체 재작성보다 기존 코드에 최소 수정으로 접근한다.
   시그니처 변경이 필요하면 기본값 있는 인자 추가를 우선한다.

7. **저장소에는 가상 데이터만** — `docs/index.html`(GitHub Pages)은 브라우저 내 계산 도구다. 저장소에는 가상 데이터(예시·fixture)만 커밋하며, 실제 조합 데이터를 절대 올리지 않는다.

## 만들지 않는 것

- Instagram API 자동 수집
- 서버·Streamlit 웹 대시보드. 웹 UI는 브라우저 내 계산 방식(`docs/`)만 허용하며, 출력은 텍스트 리포트와 동일해야 한다
- 목표 수치 자동 생성 (항상 실제 입력값 기반)
- "다음 주 액션" 자동 작성 (판단은 사람이 한다)

## 협업 방식

- 큰 구조 변경이나 대규모 구현은 사용자가 "구현해" / "수정해"라고 명시할 때만 진행한다.
- 파일을 만들거나 고칠 때 **각 파일의 역할을 설명**한다.
- 중요한 코드는 **왜 그렇게 썼는지** 설명한다.
- 에러가 나면 임시 우회가 아니라 **근본 원인**을 찾는다.
