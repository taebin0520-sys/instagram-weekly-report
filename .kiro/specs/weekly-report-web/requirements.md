# Requirements — 인스타 주간 리포트 웹버전 (weekly-report-web)

대응 문서: `design.md`, `tasks.md`
기존 스펙: `.kiro/specs/weekly-instagram-report/` (계산 규칙의 원본)

## 1. 배경

현재 도구는 `python main.py <CSV>`로 실행하는 텍스트 리포트다.
마케팅 팀원(비개발자)은 Python 설치·터미널 실행을 할 수 없어 실제로 쓰지 못한다.

## 2. 목표

팀원이 링크 하나를 열어 브라우저에서

1. 엑셀 표를 붙여넣거나 CSV 파일을 선택하면
2. 기존 Python 리포트와 **같은 결과**가 화면에 나오고
3. 결과 텍스트를 복사해 카톡·노션에 붙여넣을 수 있다.

## 3. 사용자

- 아벤투라 마케팅 팀원 (비개발자, PC·휴대폰)
- 설치, 터미널, GitHub 계정 없이 사용

## 4. 용어

- **정답지(golden)**: 같은 입력에 대한 `python main.py` 표준출력. 웹버전 출력의 비교 기준이다.
- **동일**: 줄바꿈 정규화(`\r\n`→`\n`, 끝 개행 1개) 후 **문자 단위로 완전히 같음**.
- **유효 입력**: Python 버전이 리포트를 정상 출력하는 입력 중, 날짜가 `YYYY-MM-DD`이고 UTF-8(또는 EUC-KR, R1.8)인 것.

## 5. 요구사항

### R1. 입력

- **R1.1** 사용자는 엑셀에서 복사한 표(탭 구분)를 텍스트 영역에 붙여넣을 수 있어야 한다.
- **R1.2** 사용자는 CSV 파일을 파일 선택으로 불러올 수 있어야 한다.
- **R1.3** 헤더는 기존 11개 컬럼명을 그대로 쓴다:
  `date,type,topic,reach,likes,comments,saves,shares,profile_visits,dm_inquiries,signups`
  컬럼 순서는 달라도 되고, 추가 컬럼은 무시한다 (Python과 동일).
- **R1.4** "헤더 복사" 버튼: 탭으로 구분된 11개 헤더를 클립보드에 복사한다 (엑셀 첫 줄에 붙여넣기용).
- **R1.5** "예시 데이터 불러오기" 버튼: `sample_data/instagram_posts.csv`와 **같은 내용**을 입력 영역에 채운다.
- **R1.6** WHEN 필수 컬럼이 없으면 THEN 없는 컬럼 이름을 한국어로 안내하고 리포트를 만들지 않는다.
- **R1.7** WHEN 숫자 8개 컬럼에 0 이상의 정수가 아닌 값(음수·빈칸·소수·`1,000` 같은 쉼표 포함 값)이 있으면
  THEN **몇 번째 줄 / 어떤 컬럼 / 어떤 값**을 한국어로 안내하고 리포트를 만들지 않는다.
  - 판정 기준은 Python `_is_count`와 같다: 앞뒤 공백 제거 후 숫자 문자로만 이루어진 값만 허용.
    단, 전각 숫자·위첨자는 JS가 거부한다 (design §5.4 ①).
  - 첫 번째로 문제가 발견된 컬럼 하나만 안내한다 (Python과 동일한 컬럼 순서).
  - 누락값을 0으로 자동 보정하지 않는다.
- **R1.8** CSV 파일 인코딩은 UTF-8(BOM 허용)을 먼저 시도하고, 실패하면 EUC-KR(엑셀 한글 기본 저장)로 읽는다.
  이 동작은 Python 버전에 없는 **웹 전용 보완**이며 정답지 비교 대상이 아니다.
- **R1.9** 날짜는 `YYYY-MM-DD`만 허용한다. 다른 형식이면 줄 번호와 값을 안내한다.
  (Python은 `2026/9/29` 등도 받는다 — 이 차이는 design.md 위험 ②에 기록)
- **R1.10** 줄 번호는 "헤더가 1번째 줄"인 파일 기준이다 (Python `_csv_line_no`와 동일: 데이터 첫 행 = 2번째 줄).
  단, 파일 중간에 빈 줄이 있으면 JS는 실제 파일 줄 번호를 쓰며 Python과 다를 수 있다 (design §5.4 ②).

### R2. 계산 규칙 — 기존 Python과 100% 동일

- **R2.1** 주는 ISO 8601 주(월~일). 연도도 ISO 연도 기준 (`2027-01-03(일)` = 2026-W53).
- **R2.2** 이번 주 = 데이터상 가장 최신 ISO 주. 지난주 = 이번 주 월요일 −7일이 속한 주.
  그 주 데이터가 없으면 지난주 없음으로 본다 (두 번째로 최신인 주를 쓰지 않는다).
- **R2.3** 도달 0 또는 지난주 없음 → `확인 불가`. 0%·`NaN`·`nan%`·빈칸으로 위장하지 않는다.
  계산 계층은 `null`을 반환하고, `확인 불가` 문자열 변환은 출력 계층 한 곳에서만 한다.
- **R2.4** 비율 지표(저장률·참여율)의 전주 대비는 `%p`, 절대 수치(공유·도달)는 `%`.
- **R2.5** 주 단위 비율은 합계 기준 (주 저장률 = 주 총저장 / 주 총도달).
- **R2.6** 문의·신청은 `topic == "스터디모집"`인 게시물만 합산해 `[참고 지표]` 구획에만 표시한다.
- **R2.7** 모든 비율·증감은 소수점 1자리. 반올림 결과는 Python 표기와 같아야 한다 (design.md 위험 ①).
- **R2.8** TOP 2 / 하위 1 게시물은 저장률 기준이며, 저장률 `확인 불가` 게시물은 항상 뒤로 보낸다.
- **R2.9** 주제별 구획은 주제별 게시물 저장률의 평균(확인 불가 제외) 내림차순. 전부 확인 불가면 `확인 불가`.

### R3. 출력

- **R3.1** 기존 리포트와 같은 구획 순서로 화면에 표시한다:
  제목·기간 → 이번 주 요약 → TOP 게시물 → 하위 게시물 → 주제별 평균 저장률 → 참고 지표 → 다음 주 액션.
- **R3.2** "리포트 텍스트 복사" 버튼은 `python main.py` 표준출력과 **동일한 텍스트**를 클립보드에 넣는다.
- **R3.3** 모바일(폭 360px)에서 본문 글자 16px 이상, 가로 스크롤 없이 읽을 수 있어야 한다.
- **R3.4** 복사 성공/실패를 화면에 한국어로 알린다. 클립보드 API가 막힌 환경에서는 텍스트를 전체 선택해 직접 복사할 수 있게 한다.

### R4. 데이터 보호 (최우선)

- **R4.1** 모든 계산은 브라우저 안에서만 한다. 서버 전송, 외부 API 호출, 분석·추적 스크립트를 넣지 않는다.
- **R4.2** 외부 CDN·외부 폰트·외부 이미지를 쓰지 않는다. 페이지는 저장소 `docs/` 안의 파일만 불러온다.
- **R4.3** 입력 데이터를 localStorage·sessionStorage·IndexedDB·쿠키에 저장하지 않는다. 새로고침하면 사라진다.
- **R4.4** 페이지 상단에 "입력한 데이터는 이 브라우저 밖으로 전송되지 않습니다" 문구를 표시한다.
- **R4.5** 위 R4.1~R4.3은 문서 약속이 아니라 **기술적으로 강제**한다 (Content-Security-Policy, design.md §6).
- **R4.6** 저장소는 public이므로 실제 조합 데이터를 저장소에 커밋하지 않는다 (steering 규칙 7 유지).

### R5. 구조

- **R5.1** 기존 Python 코드(`src/`, `main.py`, `tests/`)는 수정하지 않는다.
  예외: 정렬 안정성 수정 2곳 (D4·D5, fix/stable-sort).
- **R5.2** 계산 로직은 JS 파일 하나로 분리하고, 브라우저와 Node 양쪽에서 실행 가능해야 한다.
- **R5.3** 화면은 `docs/index.html` (GitHub Pages `/docs` 기준).
- **R5.4** 외부 npm 패키지를 쓰지 않는다 (Node 내장 모듈만).

### R6. 검증

- **R6.1** CI에서 모든 유효 입력 fixture에 대해 `node` 출력 == `python main.py` 출력인지 자동 비교한다.
- **R6.2** fixture는 최소: `sample_data` + 기존 엣지 케이스 7종(도달 0 ×2, 한 주만, 일·월요일, 연말 경계, 음수, 빈칸)
  + 위험 지점 전용 fixture(반올림 경계, 동률 정렬, 음수 0.0 증감).
- **R6.3** 오류 fixture는 "둘 다 거부 + JS가 안내한 줄·컬럼이 Python이 안내한 줄·컬럼에 포함됨"으로 판정한다 (design.md §5.3).
  design §5.4에 해당하는 fixture는 줄 번호 비교에서 제외한다.
- **R6.4** 기존 pytest 17개는 그대로 통과해야 한다.

## 6. 제외 범위

- Instagram API 자동 수집
- 로그인, 서버, DB
- 차트·그래프
- 여러 주 누적 분석
- 헤더 한글화
- Python 버전의 기존 동작 수정 (예외: R5.1 정렬 안정성 수정) (발견된 차이는 기록만 하고 별도 이슈로 분리)
